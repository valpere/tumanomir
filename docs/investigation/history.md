## Ключові рішення, вже ухвалені (з підставами)

1. **D_pair — робоча метрика, не ентропія.** Консенсус 5/5 рецензентів +
   власний експеримент: H@0.95 сатурує на log₂N для реальних документів
   (усі real-спеки дали 3.32 біт при N=10), дискримінує лише середня
   попарна відстань.
2. **Теорія через умовну ентропію H(C|S,θ)**, НЕ через суму дисперсій
   σ²spec+σ²model — останнє рецензенти 4/5 розібрали як категоріальну
   помилку (несепарабельні компоненти, ентропія ≠ дисперсія).
3. **K_drift strict-режим — фундамент**: детермінований лінтер розмітки,
   без LLM, найзахищеніша метрика перед senior-аудиторією. Assisted
   (LLM-парсер графа) — roadmap, успадковує похибку екстракції.
4. **D_const v0.1 — чесний lexical proxy**, не графова метрика. Повний
   RFLP-граф (Neo4j) — roadmap. Формула щільності карає прозу без
   обмежень, не прозу взагалі.
5. **Baseline зі статті — copy-floor** (транскрипція готових типів дала
   H=0 на обох приладах), не універсальна підлога. Baseline-suite —
   roadmap для `calibrate`.

## Рішення: D_pair_shape — no-go (2026-11-24, #171)

Питання, яке #106 (`naming_noise_test.go`) залишив відкритим: чи додавати поряд із
D_pair адитивне негейтоване поле `D_pair_shape` на канонізованих ідентифікаторах.
Польові дані взято з #163/#169 (dreet-dojo `req-uc` @ `32cc10f`, фікстура
`internal/dispersion/testdata/dreet-dojo-req-uc-32cc10f/`, N=9) плюс архівний
корпус `_sanity/out*/`. Рішення Val: **no-go**.

Прототип (scratch, не в репо) рахував mean-pairwise D_pair у п'яти режимах ключів:

- `base` — ключі `astfeat.go`;
- `slot` — локальні імена типів → мітки слотів з #169;
- `slotsig` — `slot` плюс сигнатури лише з типами;
- `keepmem` — усі імена типів → `T`;
- `drop` — відкинуто всі оголошені ідентифікатори.

| набір | base | slot | slotsig | keepmem | drop |
|---|--:|--:|--:|--:|--:|
| naming-noise (N=3) | 0.667 | 0.667 | 0.667 | 0.667 | 0.000 |
| naming-noise-reorder | 0 | 0 | 0 | 0 | 0 |
| dreet-dojo (N=9) | 0.246 | 0.187 | 0.182 | 0.034 | 0.013 |
| sharp A / cloud | 0.270 / 0.318 | 0.257 / 0.269 | 0.257 / 0.269 | 0.131 / 0.055 | 0.177 / 0.024 |
| fog A / cloud | 0.508 / 0.758 | 0.460 / 0.747 | 0.459 / 0.747 | 0.177 / 0.192 | 0.095 / 0.137 |
| real-si A / cloud | 0.476 / 0.742 | 0.476 / 0.681 | 0.465 / 0.679 | 0.182 / 0.182 | 0.073 / 0.117 |
| real-ragivka A / cloud | 0.718 / 0.722 | 0.671 / 0.701 | 0.668 / 0.700 | 0.091 / 0.037 | 0.093 / 0.044 |
| real-ragivka-full A / cloud | 0.598 / 0.607 | 0.589 / 0.590 | 0.587 / 0.589 | 0.130 / 0.034 | 0.127 / 0.047 |

Підстави:

- **`drop` відкинуто.** На інструменті A він перевертає sharp/fog: sharp дає 0.18, fog 0.09.
- **`keepmem` відкинуто.** Він зливає різні типи в один (real-ragivka падає з 0.72 до
  0.04), тож це колапс, а не очищення від шуму.
- **`slot` і `slotsig` безпечні, але слабкі.** На обох інструментах вони не змінюють
  порядку наборів, проте зсувають D_pair лише на 2–24%. Імена параметрів дають ≤ 0.005.
  Друга колонка додала б поверхню звіту без нової сили для рішень.
- **Гіпотеза не підтвердилась.** На dreet-dojo перейменування типів пояснюють ≈ 0.06 із
  0.25. Решта ≈ 0.18 припадає на розбіжність у наборі оголошень (зайві чи відсутні типи
  та поля). Це структура, і її вже пооголошенно показує `measure --decls` (REQ-MSR-12).
  Отже, гіпотеза «шум найменувань становить більшість D_pair» не підтверджена.
- **Фікстура naming-noise лишається на 0.67 у кожному безпечному режимі.** Вона варіює
  імена полів, а їх склеїло б лише семантичне зіставлення, яке відкинуто в #106.
- **Повернутись, коли `calibrate` (REQ-CAL-01) матиме розмічені рядки.** Розкид між
  прогонами на одному spec (`32cc10f`: 0.18 проти 0.24) вказує, що чутливість до N зараз
  важливіше питання.

## Граблі Ollama (з експерименту, вбудовано в requirements)

- thinking-режим з'їдає num_predict на складних спеках → порожній content;
  збій корелює зі складністю входу → систематичне спотворення. `think:false`.
- дефолтний num_ctx (4096) мовчки обрізає великі промпти.
- num_predict нижче природної довжини → тронкейшн → фальшивий «окремий
  кластер».
- Хмарні `:cloud` моделі ~6× швидші за локальні 30b.
